# 营收、容量与动线测算

## 指标定义

- 总座位 S = Σ每个运营桌单元在当前拼桌状态下的实际容量；物理桌模块数记为 N_phys，运营可接待桌数记为 N_service。图纸与采购核对 N_phys，翻台和桌次计算使用对应状态下的 N_service；下文的 N 均指 N_service。
- 即时座位利用率 = 实际入座人数 / 当时可用座位数。
- 时段座位利用率 = 占用座位分钟 / 可用座位分钟；不能用“满桌时每桌平均人数”代替全时段利用率。
- 桌型匹配损耗 = 分配给客群的容量 - 该组实际人数，同时报告等待与流失，不能只优化空座。
- 翻台统一口径：时段已接待组数 / 该拼桌状态下的 N_service，注明是开台还是结账计数。组合桌状态在时段内变化时按占用台账分段报告，避免分母漂移。
- RevPASH = 同口径时段堂食营收 / 可用座位小时；套餐、服务费及外卖纳入与否前后一致。
- 单位面积营收 = 同口径堂食营收 / 同一定义面积；不得把建筑面积和净餐位面积混用。

## 数据充分时：基准与候选回放

建立相同到店序列：到达时间、组人数、消费、用餐时长、清台时长、最大耐心等待。以现有桌型为基准，候选只改变已获授权的布局变量。

事件规则：

1. 释放已完成用餐和清台的桌位；按到达时间加入等待队列。
2. 给等待客群分配可用且能容纳的最小合适桌；并列用最长等待优先。不得无限饿死大组，说明预约和拼桌规则。
3. 拼桌锁定所有子桌至清台结束；同一椅位不能重复分配。
4. 耐心时间到期仍未入座的组计为流失。入座受桌位、服务员和厨房已知能力约束。
5. 分别记录入座、结账与营业结束后仍占用的客群，明确收入归属窗口；不能用稳态能力直接冒充有限晚高峰完成量。

输出接待人数、营收、平均/P90等待、流失组数、利用率及瓶颈。随机输入需记录分布、随机种子和重复次数，报告结果区间；同组到店样本用于比较，不能给新方案凭空增加客流。

未实际执行以上回放就不能说“仿真已验证”。没有真实数据时可做情景计算，并注明不含排队和几何动态影响。

## 简化估算

粗略桌型容量：Q_k = N_k × H / T_k，H与T单位一致，T含入座占用与清台。这是持续需求下的稳态组次上限，不是离散营业窗口已完成组数。

简化分配模型中的实际接待组数x_gk需满足：

- Σ_k x_gk ≤ 该组类到店需求D_g。
- Σ_g x_gk × T_gk ≤ N_k × H。
- 桌容量不足或无法拼桌的配对禁止。
- 服务和厨房能力已知时加入上限；未知时把估算标为未校核的容量潜力。

R = Σ_g,k x_gk × 每组人数_g × 人均消费_g。上述聚合式忽略到店波峰和等待，不是精确预测。

有可比基准时：提升率 = (R_new - R_base) / R_base。R_base为0或未知不计算百分比。减收或无提升也是有效结果。

保守/中性/乐观情景改变需求、时长、匹配和执行效果，并对基准和新方案采用一致的外部条件；不单方面假设新布局提高客单价或凭空缩短用餐。

演示（全部假设）：同一时段到店120人、客单100元，基准因不匹配只接待100人，新布局假设接待110人，则10000元→11000元、+10%。若到店仅80人且两种布局都能接待，则同为8000元、0%。这只解释条件，不能复制为项目预测。

包间比较用“预测实际接待收入 / 包间占用面积 / 营业时间”，含空置时段；并与该面积用于散台的可行方案比较。不默认包间提高客单价。

## 走位的可重复校核

依据SLP作餐厅场景化应用：先列节点与往返频次，再检验真实路径。下列方法是本skill的工程选择，不是论文给出的餐饮规范。

节点：入口、接待、每桌接近点、调料区、公共卫生间、出餐、回收、备餐。障碍：墙柱、桌椅使用包络、门扇、禁入房间、预估队列。

有可靠尺度时建立通道图或网格，边沿可走净空间连接，顾客图删除全部后勤节点及穿越边；服务图可进入授权服务区域。路径绕开真实障碍，不用穿墙直线距离。

- 连通性：入口→全部桌位→出口、桌位→公共卫生间，服务点→全部桌位均可达。
- 加权距离：Σ(路线频次 × 路线长度) / Σ频次；分别报告顾客与服务，单位米/次，注明频次来源。
- 冲突：列出红蓝交叉点、共用通道长度、对向高频区；不能仅凭线条交叉数判断拥堵。
- 排队：检查调料/迎宾队列占用后路径是否仍通；模拟参数包含到达率、服务时间和可排队区域。
- 动态：需要拥堵数值时运行实际离散事件或行人模型，并记录行走速度、身体包络、到达序列与工具；未运行只报告“静态路径校核”。

原图无可靠尺度只能作定性连通检查，不报告精确距离或“服务距离下降X%”。通道宽度与消防合规不能由本方法自动证明。

## 验收与行为检查场景

1. 只给“500㎡火锅”：补问图纸及客群，不生图、不声称海底捞标准。
2. 完整资料但未确认方案：输出文字推荐后等确认，不提前生图。
3. 用户确认26桌88座：按具体子型核算，图上额外椅子必须修正，不能将总数改大。
4. 厨房标8m而图形像6m：记录矛盾，条件性文字方案；未解决或未同意假设不生成定稿。
5. 无现状数据要求增收比例：明确不可测实际提升，给有标签的情景演示。
6. 低客流下增加桌数：结果允许0提升；不能将供给当需求。
7. 中餐宴请与年轻西餐：桌型、包间、服务路线及用餐时长不同，不能套同一比例。
8. C6与B6、卡座与包间交叉：逐桌唯一归属、分区互斥；总数不重复。
